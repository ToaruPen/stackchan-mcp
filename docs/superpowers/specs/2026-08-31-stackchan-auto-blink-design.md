# stack-chan 自動瞬き初期化 設計

## 背景

現在のカスタムアバターは表示できており、firmware には既に `self.display.set_blink` と、3〜6秒のランダム間隔で目を閉じて戻す瞬きタイマーが実装されている。ただし、接続直後の瞬き希望状態は無効であるため、gateway が `set_blink(true)` を明示的に送らない限り、idle 表情は静止したままになる。

gateway は ESP32 との新しいセッションでツール発見が完了すると、まだ明示的な表情指定がなければ `self.display.set_avatar({"face": "idle"})` を best-effort で送っている。本変更では、この初期化経路に自動瞬きの有効化を加える。

## 目的

- gateway と ESP32 の接続または再接続が成功した後、アバターが自動的に瞬きする。
- idle だけでなく、表示中のすべてのアバター表情で firmware 既存の瞬き処理を利用する。
- 発話中の口パクでは firmware 既存の制御に従って瞬きを一時停止し、発話終了後に再開する。
- 初期化補助の失敗によって ESP32 接続全体を失敗扱いにしない。
- firmware の再ビルドおよび再書き込みを不要とする。

## 非目的

- 瞬き間隔、閉眼時間、描画フレーム、または画像パレットを変更しない。
- 新しい表情や画像アセットを追加しない。
- firmware 起動中の Wi-Fi 設定画面など、アバター以外の画面に瞬きを重ねない。
- gateway と接続していない状態でも自律的に瞬きを開始する firmware 変更は行わない。

## 設計

### 接続初期化

`ESP32Manager._init_device` は、MCP 初期化とツール発見の成功後に次の順序で best-effort 初期化を行う。

1. 既存の自動 idle 表示を試行する。
2. 自動瞬きの有効化を試行する。
3. カメラストリームの準備処理を行う。
4. ESP32 を ready として記録する。

自動瞬きは `self.display.set_blink` に `{"enabled": true}` を渡して有効化する。接続ごとに新しい `ESP32Connection` が作成されるため、再接続時にも同じ初期化を行う。

### 明示的なユーザー操作の尊重

自動 idle 表示については既存の `avatar_render_sent` を維持する。接続初期化と競合して先に `set_avatar` が送られた場合、その表情を idle で上書きしない。

自動瞬きについても、接続単位で `blink_control_sent` を管理する。初期化と競合して先に明示的な `set_blink(true/false)` が送られた場合は、自動の `set_blink(true)` を送らない。これにより、ユーザーが意図して瞬きを無効にした状態を初期化処理が上書きしない。

`set_avatar` と `set_blink` の追跡は独立させる。明示的な表情が既に指定されていて自動 idle が抑制された場合でも、明示的な瞬き指定がなければ自動瞬きは有効になる。したがって、idle 以外の表情でも通常どおり瞬きする。

### firmware 既存動作との関係

gateway が有効にするのは firmware 既存の瞬きタイマーである。表情画像、閉眼画像、およびパレットは現在書き込み済みの avatar set をそのまま使う。

口パクシーケンス中は firmware が瞬きタイマーを抑制し、シーケンス終了時に最新の `blink_desired_` を参照して再開する。したがって gateway 側で発話開始・終了ごとの追加制御は行わない。

アバターを off にした場合の停止と、その後の復帰も firmware 既存の状態保持に委ねる。

### エラー処理

自動 idle 表示と自動瞬きは互いに独立した best-effort 処理とする。

- 自動 idle 表示が失敗しても、自動瞬きの有効化を試行する。
- 自動瞬きが例外、タイムアウト、または MCP エラーを返した場合は warning を記録する。
- いずれの失敗でもカメラ準備と ready 遷移を継続する。
- MCP 初期化またはツール発見自体が失敗した場合は、どちらの自動処理も実行しない。

## テスト方針

gateway の単体テストを Red → Green で追加・更新する。

- 正常な新規接続で `set_avatar(idle)` の後に `set_blink(true)` が1回ずつ送られる。
- 新しい接続を作った再接続でも、両方が再度送られる。
- 明示的な `set_avatar` が先行した場合は自動 idle のみ抑制され、自動瞬きは送られる。
- 明示的な `set_blink(false)` が先行した場合は、自動 `set_blink(true)` が抑制される。
- ツール発見に失敗した場合は、自動 idle と自動瞬きを送らない。
- 自動 idle が失敗しても自動瞬きを試行し、ready 遷移を継続する。
- 自動瞬きが MCP エラーまたは例外になっても warning を記録し、ready 遷移を継続する。
- `ESP32Connection.call_tool` が `set_blink` の送信を接続単位で記録する。

実装後は gateway の対象テスト、全テスト、Ruff を実行する。ローカル gateway を更新・再起動し、実機の接続後に idle 表情が表示され、遅くとも既存の最大間隔である約6秒以内に瞬きが始まることを目視確認する。発話中の口パクと発話後の瞬き再開も確認する。

## 受け入れ条件

- gateway 起動後または ESP32 再接続後、追加の手動コマンドなしで表示中のアバターがランダム間隔で瞬きする。
- idle 以外の表情へ切り替えても瞬きが継続する。
- 口パク中は描画が競合せず、終了後に瞬きが再開する。
- 明示的な `set_blink(false)` は同一接続内で自動初期化に上書きされない。
- 自動瞬き初期化の失敗だけでは ESP32 が利用不能にならない。
- firmware の再書き込みを必要としない。
